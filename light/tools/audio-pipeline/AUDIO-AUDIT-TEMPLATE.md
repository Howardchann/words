# 音频审查清单模板（只记录状态，不生成或上传音频）

> 音源链路：Microsoft Azure Neural TTS（美音例句/语法例句）与既有单词音源；由音频负责 AI 通过云端 API 生成并上传。密钥放在本机环境变量/密钥管理中，不写进清单或仓库。
>
> 本表必须把三件事分开记录：**代码路由正确**、**真实资产已生成/上传**、**实际读音已核验**。任一状态不能推定另外两项完成。

## 状态定义

- `未检查`：尚无证据。
- `代码已核验`：检查了代码中的桶、路径、ai/hash、缓存版本和回退路由；不代表云端存在文件。
- `生成/上传待核验`：音频任务已提交，但尚未验证云端 key 与文件可读性。
- `资产已核验`：在云端确认目标 key 存在、可下载、文件非空；不代表读音正确。
- `读音已核验`：实际播放或听取了音频，并核对目标词性/义项/口音；不能仅凭文件存在打勾。
- `需重生成`：已确认资产内容错误或缺失，交由音频负责 AI 处理；本次内容修复流程不自动生成。

## 批次核验要求

1. 内容/代码修改后，先用脚本核对路由、ai 唯一性、文本哈希和缓存根；这一步只记为 `代码已核验`。
2. 音频负责 AI 生成/上传后，逐 key 核对云端存在性和文件可读取；记为 `资产已核验`。
3. 对词性/读音存在歧义的条目实际听音确认；记为 `读音已核验`。无法听辨时保留未核验，不用 API 成功状态替代。
4. 如同路径同名文件被替换，检查并按项目规则更新 `CACHE_ROOT`；不要清单里写“完成”但遗漏旧设备缓存。
5. 本清单不存 API key、访问令牌或任何秘密。
