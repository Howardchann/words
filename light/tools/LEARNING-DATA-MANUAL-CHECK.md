# light 学习数据修订：真机功能验收清单

> 本清单只验收界面、交互、音频路由和学习进度保护。使用者无需判断英语知识是否正确；词性、释义、音标和翻译的内容审查由数据审计负责。

## A. 今日页（重点：主卡 / 副卡）

- [ ] 找到至少一个多义词（建议 `sow`、`use`、`moderate` 或 `record`），确认主卡与副卡顺序合理。
- [ ] 主卡和副卡各自显示正确的词性、释义、英美音标、英文例句和中文翻译；文字不重叠、不截断。
- [ ] 主卡与副卡分别点击美音、英音单词喇叭和例句喇叭，确认播放的是对应卡片，不会串卡。
- [ ] 快速切换下一个词后，旧卡的释义、例句或音频状态不会残留到新卡。
- [ ] 完成一次打卡前后，学习天数、已学词数、当前课程位置正常。

## B. 搜索页

- [ ] 搜索 `sow`、`use` 或 `moderate`，确认搜索结果包含统一的主/副义项，不重复嵌套显示两次副卡。
- [ ] 点击副义项的美音/英音和例句喇叭，确认音频编号与该副义项一致。
- [ ] 清空搜索、连续更换关键词、滚动结果列表，确认列表不空白、不闪动、不误跳转。
- [ ] 搜索普通词（无副卡）时布局保持原样，没有空白副卡占位。

## C. 复习页（随机、到期、重点词）

- [ ] 随机复习和到期复习各检查一张有副卡的词；副卡内容、间距、音标行、例句行完整。
- [ ] 中文显示/隐藏按钮仍按原规则工作；副卡中文释义和例句翻译不会在隐藏状态下提前泄露。
- [ ] 主卡与副卡喇叭分别播放正确读音；快速连点不会导致卡片错位、重复触发或长期转圈。
- [ ] 收藏、取消收藏、跳到下一词、切换随机/到期 tab 均正常。
- [ ] 重点词列表中有副卡的词只显示简洁提示，不把副卡内容挤坏原来的磁贴布局。

## D. 小屏幕与视觉检查

- [ ] 用实际手机屏幕检查长单词、长释义和较长例句；无横向溢出、文字覆盖喇叭、按钮挤到屏外。
- [ ] 页面滚动到底部后，底部导航和安全区域不遮住内容。
- [ ] 连续打开今日 / 搜索 / 复习 / 工具页面，布局和主题颜色稳定。
- [ ] 若出现问题，记录手机型号、微信版本、页面、操作步骤，并附截图/录屏；不需要自行判断英语内容。

## E. 音频交接（由负责音频的 AI 完成，不要求用户听辨英语）

- [ ] 处理 `tools/audio-pipeline/data/pending-sentence-audio.json` 中 14 条例句任务。
- [ ] 每条任务分别记录生成、上传、实际听核状态；不能仅因文件存在就标记听核通过。
- [ ] 重新生成后核对云端对象 key、文件时长/大小及 manifest；如覆盖同名缓存资产，检查 `utils/speech.js` 的 `CACHE_ROOT` 是否需要升级。
- [ ] 在报告中写明实际使用的 Microsoft/Azure 语音服务、voice ID、locale、语速参数；仓库中未找到足以确认用户所说音色的生成脚本，不能凭记忆猜是 Aria、Ana 或其他声音。
- [ ] 对同形异音词逐项核对主/副卡的文本、词性、IPA、`ai` 编号和实际音频；记录异常和重新生成结果。

## 通过标准

- A–D 无阻断级功能/布局问题；E 的音频状态有证据且如实记录。
- 任何未实际执行的检查保持未勾选，不用静态代码扫描结果替代真机结果。
