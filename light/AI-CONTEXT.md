## 问题边界（2026-09-27 用户定性 + 09-27/09-29 录屏逐帧定性 + 09-29 真机收敛）

1. ⚠️ **deep-link（设置页→复习页指定 tab）极短残影 —— 待解决**：盖罩（veil）+跨栈预切换方案照搬 cloud，残影仍在（残影内容恒为浅色画面）。**已知过渡帧（中转桥垫帧）方案在本实例形态下不会产生残影**——过渡桥 2026-09-26 真机实验中浅色浏览正常，但该方案因深色形态闪白被整体舍弃，本实例不单独启用；残影保持待解决。
2. ✅ **冷启动后首次点击 tab「顶部闪一帧」—— 已解决（v1.1.40 + v1.1.41，真机通过）**：

   **（a）早期定性（机制，仍然有效）**
   - **现象修正（推翻「系统深色才闪」的旧定性）**：与色系**无关**。触发条件 = **手机后台没有本小程序（被杀/清除）后再次进入，首次点击今日之外的每个 tab**；首页（今日）不闪——它是启动页，webview 常驻已渲染。
   - **逐帧实锤**（录屏 1000129736.mp4，24fps）：每次切 tab 存在 **1~2 帧（约 40~80ms）「容器底色帧」**——整屏窗口底色、自定义导航未绘制、仅系统状态栏与胶囊位可见、隐约可见新页内容虚影；随后 1 帧内完整渲染。
   - **机制定性**：tab 页 webview 冷创建的**首绘帧**——窗口容器底色（app.json window.background）先上屏，页面背景与自定义导航 1~2 帧后才绘制。感知强度**只取决于「首绘帧颜色」与「元素颜色」的色差**：色差大就显眼，色差小就不可感知。全行业同构小程序均存在，官方无「预绘制页面背景」API。

   **（b）解决（v1.1.40 → v1.1.41）**
   - **根因链**：窗口容器底色恒为 `#F3F8EF`（本实例无 darkmode，静态），而导航栏是品牌绿 `#176B5B` → 顶部大面积色差 → 冷启动首访每页都闪。
   - **方案 A（用户拍板，v1.1.40）**：自定义导航栏底色改为**与窗口底色同色** `--nav-bg:#F3F8EF`（`--nav-fg:#24332F`）→ 首绘帧与终态零色差，感知消除；品牌绿退守内容区（按钮/tab 选中态/小标题不变）。**回退绿顶只改 app.wxss 一行 token**。
   - **配套修正（v1.1.41）**：导航前景改浅后，**状态栏字色是另一条独立通道**——四页 json `navigationBarTextStyle` white→black，否则系统状态栏（时间/电量/信号）白字在浅底上不可见。**教训：改顶部配色必须同时查「CSS 变量 --nav-bg/--nav-fg」与「页面 json navigationBarTextStyle」两处**。
   - 真机结论（09-29）：**冷启动不闪、切 tab 不闪、状态栏清晰可见**。
   - 早期候选（保留备查，未采用）：① 每页 json `backgroundColor` 改绿（有 iOS 回弹露绿边副作用）② `initialRenderingCache:"static"` 首绘缓存 ③ Skyline 引擎（兼容风险大）④ 设计层弱化。最终采用的是「导航层与窗口底色同色」，无副作用。
3. ⚠️ **冷启动首访「白卡浮现」1~2 帧 —— 已知残留，用户决定不动（v1.1.42）**：同源机制的剩余表现——白卡 `#FFFFFF` 与窗口底色 `#F3F8EF` 色差 Δ≈12，冷启动首次进入某页时白卡会有一帧浮现；第二次进入（webview 已建）即无。**有意保留**：白卡是当前唯一高光面，为 1~2 帧改掉不划算；**留待 SPA 化时一并重做卡片体系**（见下节）。对照数据：导航/页底 Δ=0 不闪；「学习提示」卡浅绿底 `#F0F7F3` Δ≈3 从不闪；白卡 Δ≈12 可见浮现。

其他说明：切主题闪旧主题类问题在本实例结构性不存在（无主题切换）；合成器缓存帧机制仍在（后台页延迟重绘），缓存帧内容恒为浅色正确画面。

## SPA 化思路（2026-09-29 结论 · 卡片与配色体系的最终解法）

**SPA = 单 webview + 页内条件渲染**（不用 navigateTo/switchTab 建多页）。它是「首绘帧」与「缓存帧」两个家族问题的**结构性解法**：

| 现问题 | 成因 | SPA 后 |
|---|---|---|
| 各页首访首绘帧闪（顶部/白卡浮现） | 新页面 = 新 webview 冷创建，窗口底色先上屏 | 无「新页面创建」→ 消失 ✅ |
| deep-link 残影 | 后台页 webview 帧停在旧画面（合成器缓存帧） | 只有一个 webview，无后台缓存帧 ✅ |
| 跨主题翻转后首点 tab 闪白 | 切主题后页面重建 | 同上 ✅ |

**两点诚实的边界**（决策时必须知道）：
- 小程序**冷启动那一帧仍存在**（app 第一次上屏只可能有一次，可用启动页兜底），SPA 消除的是「每次首访页面都闪」；
- 改动大、风险高（需自实现路由/tab 切换/页面状态），**已评估后搁置**，非必要不启动。

**关键推论（本次讨论的核心）**：**SPA 后「窗口底色」不再是硬约束**（不再有逐页首绘帧去对齐它）→ 卡片配色彻底自由，白卡、阴影、描边可以放开用，不必再迁就 1~2 帧。因此：

- **卡片体系的重做（是否统一浅底、是否加描边、是否保留白卡）留待 SPA 时一并决定**，现在不动是最省成本的策略；
- 本次讨论已定型的判断（可复用）：**「区分」优先用细线（描边/竖条，面积小 → 自身几乎不产生闪现），「底色」尽量贴近窗口底色（大面积 → 必然闪）**；
- 卡片配色候选（备查，未采纳）：**B** 全卡浅绿底 `#F0F7F3` + 描边（比页底**深** → 观感是内嵌/凹陷）；**C** 全卡略亮底 `#F8FBF6` + 描边（Δ≈5，比页底浅 → 保住「浮起卡片」直觉，防闪与观感折中更好）；现状 = 白卡 + 阴影无描边。
- v1.1.42 只把**「学习提示」卡**按 B 的**手法**改造（浅绿底保留 + 细描边 + 左侧绿竖条），作为「区分走线条」的最小实验；其他卡片维持白卡。

## 单词搜索（v1.1.46）

**入口**：今日页自定义导航栏**左区插槽**里的放大镜（`.nav-search`，热区 30px / 图标 22px）→ `navigateTo` 搜索页。左区本身宽 ≈94px（与右侧胶囊区对称，用来保证标题居中），`nav-bar` 组件为此从「纯占位」升级为「可选容器」（`box-sizing:border-box` + 内部 `padding-left`，**宽度不变所以标题不偏**）；同时新增 `back` 属性给非 tab 页（搜索页）用，tab 页不传即零变化。返回键用字符 `‹` 而非 SVG —— 颜色直接继承 `--nav-fg`，深浅主题零成本适配。

**搜索**：纯前端内存过滤 `utils/data.js#searchWords()`，8000 词单次遍历 <5ms，不发请求、离线可用。排序 **完全匹配 > 英文前缀 > 英文包含 > 中文释义包含**（组内按词表序 = 由易到难 = Day 升序）；**完全匹配必须置顶**，否则搜 good 会被 goods/goodbye 顶到后面，用户会以为搜错了。默认最多返回 60 条，`total` 始终是真实命中数（超出时页头提示「仅显示前 N 个」）。

**结果行**与今日页词行同构（v1.1.51 后 = 单词 + 词性同行 / 美音·英音双音标模块 / 词义 / 例句+喇叭），额外挂一行 `Day N · 第X周 周X ›`。

**点击归属铁律（v1.1.49 定稿，v1.1.51 随方案 A 更新）：整张卡片 = 跳转，只有美/英音标模块与例句喇叭 = 朗读。**
即 `catchtap` 只允许出现在 `.ipa-mod`（音标模块，含内嵌喇叭。v1.1.51 前为左侧 `.word-speak`）与 `.ex-speak`（例句喇叭）上，**其它任何位置都不许拦点击**。初版把例句文本也写成 `catchtap`（点了朗读例句，与今日页一致），但例句 `.word-example` 是 `flex:1` 撑满整行、还常折两行，**是卡片里面积最大的一块** —— 用户「点卡片」时经常落在它上面，表现就是「偶发点了不跳」（真机两次反馈后定位到此）。要朗读例句请点它右侧的喇叭图标。搜索结果页提示语同步改为「点音标模块只朗读，不跳转」。

**点词条 → 跳到该词所在的 Day 并定位高亮**：

- 通路复用周计划那套 `globalData.jumpDay`（`switchTab` 不能带参），再加一个 `jumpWord`；今日页 `onShow` 消费后**立即清空**，否则下次切 tab 回来会再定位一次；
- 今日页词行加锚点 `id="w{{index}}"`；渲染后 `pageScrollTo`（量不到位置就重试，上限 5 次，v1.1.49 由 3 次放宽），目标行上移 140px 避免贴着屏幕顶；`.word-row--hl` 底色闪一下再淡出，2s 自动清；
- `dayOfWordIndex()`（二分 `DAY_OFF` + 「每周 5 个学习日 + 周末 2 天」）换算**日历天**，口径必须与 App 的 Day 一致。已验证：390 个学习日全部落在周一~周五（周六日无新词，不会跳空）；随机抽 300 词，搜索首条 = 该词本身且 `getDay(该 Day).v` 确含此词，异常 0；全库 8000 条无重复词；
- **不走 deep-link**（是应用内 `switchTab`，等价用户手点 tab），与「问题边界」里那个待解决的 deep-link 残影无关。

**两个刻意的取舍**：

1. **关键词只存本地 storage**（`ielts-365-search-kw`），**不进 `store`** —— `store.set()` 会 `schedulePush()` 触发云同步，纯 UI 现场不该混进要上云的业务数据；
2. 从结果跳走时 `switchTab` 会**销毁搜索页**（小程序规则：关闭所有非 tab 页）→ 回到搜索页时按存下的关键词**自动恢复关键词与结果**，做到跟没离开一样；只有无历史关键词时才自动聚焦弹键盘。

**未做**：结果行不带收藏按钮（会把行挤窄，刚调好的音标一行排版有再次被压的风险），收藏仍走今日页星标。

**⚠️ 坑：input 的 `focus` 只做「同步」不做「控制」（v1.1.47 修复）**

初版在 `onInput` 里写了 `setData({ kw, focus: false })`，本意是「用户已开始输入，撤掉自动聚焦」——结果是**每按一个字母输入法就缩回去，一个单词都打不完**。根因：在微信里 `setData({ focus:false })` 并非「取消愿望」，而是**主动调 blur**，等价于「收起键盘」（社区里就是用这一行来手动收键盘的）；叠加页面重渲染可能把陈旧的 `focus:false` 再应用一次，于是变成反复弹出/消失。

正确做法（现状）：

- `onInput` 里**绝不碰 `focus`**，只回写输入内容（`value` 回写同值是无操作，官方文档的示例就是这个写法，安全）；
- `focus` 只在真实焦点事件里回写，保证 `data.focus` 与输入框真实状态一致：`bindfocus → focus:true`（仅在当前为 false 时）、`bindblur → focus:false`（仅在当前为 true 时）；
- **input 上加 `hold-keyboard="{{true}}"`**（2.8.2+，＝「focus 时点击页面不收起键盘」）：点 × / 点词条都不会让输入框失焦。**这是「点 × 键盘闪一下」的解法** —— 原先点 × 先失焦、`onClear` 里再 `focus:true` 拉回来，一来一回就是那一下闪动；现已删掉 `onClear` 的 focus 写入；
- 顺带把 `wx.setStorageSync(关键词)` 从「每次按键」挪到防抖后的 `_run()` + `onUnload()`——安卓上同步写存储是阻塞调用，打字时不该每键一次。

**点词条跳转的稳健性（v1.1.48 → v1.1.49）**：

1. 结果行的跳转数据全部挂 `dataset`（`data-w` + `data-day`），**不要回头查 `this.data.list`**（列表会被防抖/朗读回调重写）；
2. `switchTab` 补 `fail` 重试（并发 switchTab 会静默失败，表现为「点了没反应」），彻底失败要 toast，**绝不静默 return**（`dataset` 缺字段时同样 toast）；
3. **重入锁必须能自愈**（v1.1.49 的关键修正）：安卓上存在 `switchTab`「既不回调 success 也不回调 fail」的形态，硬锁一旦卡住 → 之后**每次**点击都静默失效（现象＝「偶发点了不跳」，且会一直坏到页面重建）。所以锁写成「有效期 1.2s + 1.6s 看门狗」，两条路径都释放；`onUnload` 里清掉看门狗（switchTab 成功会销毁本页，避免销毁后 setData）；
4. **行内要有反馈**：点击后该行的 `›` 变成「跳转中…」（`data.jumpingW`），失败/超时自动复原 —— 这样「点到了但没跳」和「根本没点到」从此可区分；
5. 朗读状态回调**加同值守卫**再 `setData`：该回调里常常只有 1~2 个字段变化，而 `setData` 不做深度 diff，同值也会把 60 行列表整棵重渲染（低端机上就是「播放时卡一下」）。⚠️ 守卫键必须是「**文本 + 已亮字符数**」而不能只比字符数（v1.1.50 教训）：上次播放结束 `_lit` 归 0 后，新播放开始 `lit=0` 与旧值相等 → kara 字段残留空串而 `playingText` 已切换 → **文本先消失、等第一个进度回调才显现**；
6. 今日页 `_scrollToWord` 遇到 `findIndex` 找不到词时**按未上屏重试**（120ms×5），不要直接 return；
7. 喇叭等行内子元素加了 `hover-class` 的，务必同时加 `hover-stop-propagation="{{true}}"`（v1.1.50）：否则子元素的 `touchstart` 冒泡会激活行级 `hover-class`，用户看到「点喇叭整个卡片变色」。

- **归一化流水线**（`_ipa_build/uk_norm.js` 是唯一实现，`harmonize.js` 调它重刷）：
  1. 字符降级 `ɹ→r ɫ→l ɡ→g`；
